# Swagger UI, OpenAPI & AsyncAPI в Spring Boot
## Зависимости (build.gradle.kts)
- `spring-boot-starter-web`: Базовая зависимость для REST API. Swagger документирует именно эти эндпоинты.
- `springdoc-openapi-starter-webmvc-ui`: Основной движок для OpenAPI 3. Генерирует JSON/YAML спецификацию и предоставляет встроенный Swagger UI.
- `spring-boot-starter-validation`: Позволяет Swagger-у видеть ограничения полей (`@Min`, `@NotBlank`) и отображать их в UI как правила валидации.
- `io.github.springwolf:springwolf-kafka`: Аналог springdoc, но для асинхронных протоколов. Сканирует `@KafkaListener` и генерирует AsyncAPI схему.
- `io.github.springwolf:springwolf-ui`: Визуальный интерфейс для просмотра AsyncAPI схем.

## Разметка 

### OpenAPI (Swagger)

1. **Добавление зависимости**: `springdoc-openapi-starter-webmvc-ui`.
2. **Конфигурация**: В `application.yml` задаются пути `/api-docs` и `/swagger-ui.html`.
3. **Метаданные**: Создание бина `OpenAPI` в `OpenAPIConfig.java` для описания версии, контактов и лицензий.
4. **Разметка аннотациями**

#### Аннотации OpenAPI / Swagger

- `@Tag`  
  Группирует эндпоинты в Swagger UI. Обычно ставится над контроллером.  
  Позволяет задать имя группы и описание.

- `@Operation`  
  Описывает конкретный HTTP-метод.  
  Используется для задания краткого описания `summary` и подробного описания `description`.

- `@Parameter`  
  Описывает отдельный параметр метода: path-параметр, query-параметр, header и т.д.  
  Позволяет добавить описание, пример значения и дополнительные ограничения.

- `@ApiResponses`  
  Контейнер для нескольких вариантов HTTP-ответов.  
  Используется, когда нужно явно описать успешные и ошибочные ответы метода.

- `@ApiResponse`  
  Описывает один возможный HTTP-ответ: код, описание и тело ответа.  
  Например: `200`, `201`, `400`, `404`, `500`.

- `@Content`  
  Описывает содержимое HTTP-ответа или запроса.  
  Обычно используется внутри `@ApiResponse` для указания `mediaType` и схемы данных.

- `@Schema`  
  Описывает DTO, модель или отдельное поле модели.  
  Позволяет задать описание, пример, тип, формат, обязательность и реализацию класса для схемы.

#### Аннотации Spring MVC, влияющие на OpenAPI

- `@RestController`  
  Помечает класс как REST-контроллер.  
  Springdoc сканирует такие классы и добавляет их методы в OpenAPI-спецификацию.

- `@RequestMapping`  
  Задает базовый путь для контроллера или конкретный маршрут для метода.  
  Используется Swagger-ом для построения URL эндпоинтов.

- `@GetMapping`  
  Описывает HTTP GET-эндпоинт.  
  Обычно используется для получения данных.

- `@PostMapping`  
  Описывает HTTP POST-эндпоинт.  
  Обычно используется для создания ресурса или отправки данных.

- `@PathVariable`  
  Указывает, что параметр метода берется из части URL.  
  Например: `/users/{id}`.

- `@RequestBody`  
  Указывает, что параметр метода передается в теле HTTP-запроса.  
  Swagger отображает такое тело как request body.

- `@ResponseStatus`  
  Задает HTTP-статус ответа метода.  
  Например, `201 Created` при создании ресурса.

#### Аннотации валидации

- `@Valid`  
  Включает проверку DTO по Bean Validation-аннотациям.  
  Используется рядом с `@RequestBody`, чтобы валидировать входящие данные.

- `@Positive`  
  Проверяет, что числовое значение положительное.  
  Springdoc может отображать это ограничение в Swagger UI.

- `@NotBlank`  
  Проверяет, что строка не `null`, не пустая и содержит хотя бы один непробельный символ.  
  Используется для обязательных текстовых полей.

### AsyncAPI (Springwolf)

1. **Добавление зависимостей**: `springwolf-kafka` и `springwolf-ui`.
2. **Конфигурация**: Настройка свойств `springwolf.docket.*` в `application.yml` или через бин `AsyncAPI`.
3. **Разметка аннотациями**:

#### Аннотации Springwolf / AsyncAPI

- `@AsyncListener`  
  Документирует потребление асинхронных сообщений.  
  Обычно используется над методом, который обрабатывает сообщения из брокера.

- `@AsyncPublisher`  
  Документирует публикацию асинхронных сообщений.  
  Используется над методом, который отправляет сообщение в брокер.

- `@AsyncOperation`  
  Описывает асинхронную операцию.  
  Позволяет указать канал, описание операции и серверы, например Kafka.

- `@KafkaTopicOperation`  
  Описывает Kafka-специфичные параметры операции.  
  Используется для детализации топика, типа сообщения и другой информации, связанной с Kafka.

#### Аннотации Kafka

- `@KafkaListener`  
  Помечает метод как обработчик сообщений из Kafka-топика.  
  Springwolf может использовать такие методы для построения AsyncAPI-документации.

### Spring Boot и конфигурационные аннотации

- `@SpringBootApplication`  
  Главная аннотация Spring Boot-приложения.  
  Объединяет `@Configuration`, `@EnableAutoConfiguration` и `@ComponentScan`.

- `@Configuration`  
  Помечает класс как источник Spring-конфигурации.  
  Используется для объявления бинов и настройки приложения.

- `@Bean`  
  Помечает метод, результат которого должен быть зарегистрирован в Spring-контейнере как бин.  
  Например, используется для настройки OpenAPI или CORS.

- `@Service`  
  Помечает класс как сервисный компонент приложения.  
  Такие классы автоматически обнаруживаются Spring-ом при сканировании компонентов.

- `@Override`  
  Стандартная Java-аннотация, показывающая, что метод переопределяет метод родительского класса или интерфейса.

### Lombok-аннотации

- `@Data`  
  Генерирует getters, setters, `toString`, `equals` и `hashCode`.

- `@NoArgsConstructor`  
  Генерирует конструктор без аргументов.  
  Часто нужен для сериализации и десериализации DTO.

- `@AllArgsConstructor`  
  Генерирует конструктор со всеми полями класса.

- `@RequiredArgsConstructor`  
  Генерирует конструктор для `final`-полей и полей с `@NonNull`.  
  Удобен для constructor injection в Spring.

- `@Slf4j`  
  Добавляет в класс логгер `log`.  
  Используется для логирования без ручного создания `Logger`.

## OpenAPI vs AsyncAPI

| Характеристика     | OpenAPI (Swagger)             | AsyncAPI                         |
|:-------------------|:------------------------------|:---------------------------------|
| **Взаимодействие** | Синхронное (Request-Response) | Асинхронное (Event-Driven)       |
| **Протоколы**      | HTTP(S)                       | Kafka, RabbitMQ, MQTT, WebSocket |
| **Фокус**          | Эндпоинты (Paths)             | Каналы (Channels), Сообщения     |
| **Spring Boot**    | `springdoc-openapi`           | `springwolf`                     |

## Генерация: Способы и инструменты

### Генерация схемы из кода (Code-First)
- **Как:** Используется в этом проекте. Библиотеки сканируют аннотации и рефлексией строят схему.
- **Плюсы:** Документация всегда соответствует коду.
- **Минусы:** Код "загрязнен" аннотациями документации.

### Генерация кода из схемы (Design-First / Contract-First)
- **Инструменты:** [OpenAPI Generator](https://openapi-generator.tech/), [Swagger Codegen].
- **Как:** Сначала создается YAML файл (контракт), затем плагин генерирует интерфейсы контроллеров и DTO.
- **Плюсы:** Строгое соблюдение контракта, параллельная разработка фронта и бэка.
